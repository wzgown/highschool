Agent Architecture · 折桂登高 中考志愿顾问

AI 顾问：一个不会编数字的对话 Agent

用六节点状态图把一次「中考志愿咨询」拆成 意图识别 → 规划 → 取数 → 综合 → 校验，并以一道确定性程序化校验守住底线——回答里每一个数字，都必须能溯源到一次真实的工具查询。

6 状态图节点 6 意图 14 受控工具 反思重规划 ≤ 2 全局并发 10 · 会话串行 工具 5s / LLM 60s LLM OpenAI 兼容 可插拔

这个 Agent 的灵魂不是「会调工具的 LLM」，而是 数据驱动反幻觉：Synthesizer 被硬性要求「回答中的每一个数字都必须来自工具查询结果」，而 Reflection 节点用一道确定性的程序化校验（verifyReply）逐字核对——任何无法在工具结果中溯源的数字，都会触发重规划。LLM 负责语言，校验器负责真相。

§ 01

六节点状态图

每个节点是一次独立的 LLM 调用或确定性步骤，产出写入共享 State，逐节点 checkpoint 落库。状态图本身不持有运行时状态——graph.Run() 是个从 Router 推进到 End 的循环。

NODE ①

Router · 意图识别

LLM · temp 0 · 强 JSON · 300 tok
  • 识别 6 类意图（policy_qa / data_query / recommendation / simulation / result_interpretation / off_topic），抽取 7 类槽位
  • 注入「当前时间」上下文，防止把「今年」当成训练记忆里的旧年份
  • 槽位标准化：一模→MOCK1、区名补「区」
  • 守门置信度 < 0.4 或 off_topic → 直接拒答，不消耗后续节点
NODE ②

Planner · 任务规划

LLM · temp 0 · 强 JSON · 500 tok
  • 从 Tools.Specs() 里选工具，产出 steps[]（建议 1–4 步）
  • 过滤掉 LLM 幻觉出的未注册工具名
  • 守门recommendation 缺必填槽位（区 / 分数 / 考试类型）→ 转 Clarify
  • 空计划（纯政策问答）→ 跳过 Executor 直奔 Synthesizer
NODE ③

Executor · 并行执行

errgroup 并发 · 无 LLM
  • 所有 Step 经 errgroup 并发执行，单工具 5s 超时 + panic recover
  • 每个工具产出双载荷：ForLLM（紧凑 JSON 给模型）+ Cards（结构化卡片给前端）+ Summary（给人看的摘要）
  • 守门单步失败降级返回 error JSON，不中断整轮；metrics + span + trace 全留痕
NODE ④

Clarify · HITL 追问

模板化 · 无 LLM
  • 按缺失槽位取追问模板（区 / 分数 / 考试类型 / 初中），设置 PendingQ
  • 本轮结束，会话置 waiting_input
  • 下轮用户回答 → resumeFromClarify 把答案并入 Slots，从 Planner 继续
NODE ⑤

Synthesizer · 结果综合

LLM · temp 0.3 · 800 tok
  • 把工具结果注入为「回答的唯一数据来源」，带最近 N 条历史
  • 8 条硬规则：数字必须来自工具、800/750 分制不可混用、分数线必带年份与涨跌、推算数据标口径、结尾固定免责声明、≤400 字
  • 这里只产「草稿回答」，是否放行由 Reflection 决定
NODE ⑥

Reflection · 校验重规划

确定性校验 + 可选 LLM
  • 核心verifyReply：逐数字核对可否溯源（见 §02）
  • 数据类意图未调工具却出现数字 → 判幻觉，拦截
  • 未通过 → 清空 ToolResults，带失败原因回 Router（≤ 2 次）
  • 连续未通过 → 降级话术 + 保留卡片（数据照给，话术不误导）
§ 02

反幻觉内核：数字溯源

Reflection 节点的确定性校验规则。回答里提取出的每个数字，都要在「工具结果的容差集合」里命中——直接命中、两数之差（涨跌 / gap）、白名单常量、或合法年份，四者居其一才算通过。这是一道硬规则，不依赖 LLM 自觉。

情形规则判定
合规数字 命中工具结果集合——直接命中 / 两数之差（gap = 分数 − 线）/ ±0.05 容差 通过
政策常量 白名单：批次志愿数（1 / 2 / 15）、分制满分（750 / 800）、控制线（501 / 615）等 system prompt 中的规则数字 通过
年份 1900–2100 范围内的整数（不视为需要溯源的数据） 通过
无源数字 数据类意图（data_query / recommendation / result_interpretation）未调用任何工具却给出数字 拦截 → 重规划
无法溯源 数字不在容差集合、不在白名单、非年份 → 判为模型编造 拦截 → 重规划
§ 03

受控工具集

ToolRegistry 统一注册、统一 5s 超时与 panic 保护；Specs() 按名排序保证喂给 LLM 的 tools 参数稳定。全部 12 个数据工具只读，2 个引擎型工具在 P2 接入。每个工具同时产出给模型的 JSON 与给前端的卡片——一次取数，两处消费。

分制红线工具层强制校验分制：名额分配（到区 / 到校）是 800 分制（含综评 50 分），平行志愿 1–15 是 750 分制。分数超过该批次满分直接拒绝（locate_score 等），从源头杜绝 800/750 混用。

§ 04

分层架构

DDD 分层 + 依赖组装集中在 agent_connect.go。状态图与业务编排解耦：Graph 只依赖 LLMClient / ToolRunner / Store 三个接口，便于单测与替换 provider。

§ 05

工程化：让它在生产里稳得住

状态图只是核心；真正让它能上线的是一圈横切机制——并发、限流、内容安全、降级、可观测、持久化。每一项都对应代码里一处明确的设计。

并发控制

全局信号量闸（默认 MaxLLMConcurrency=10，等满 30s 超时回「咨询人数较多」）+ 会话级 sync.Mutex（同一 session 串行，防双击 / 多端并发竞态）。

限流

按 device_id 的每日消息配额（DailyQuota），用完提示明天再来，并在用户层引导去用「智能推荐」。

内容安全（双向）

输入 msgSecCheck：违规直接拒答，不消耗 LLM。输出检测：违规替换为兜底话术并清空卡片。微信侧不配置时降级为 NoopChecker。

降级链

节点失败 → 兜底话术；工具失败 → 不中断整轮；Reflection 失败 → 重规划 → 降级话术；StepBudget（默认 12）耗尽 → 兜底。任何路径都不裸抛给用户。

可观测

OTel span（节点 / 工具 / LLM 调用，关闭时 noop 零开销）+ trace 落库（llm / tool / node 三类，含 token 与延迟）+ metrics（ObserveLLMCall / ObserveToolCall / IncChatRequests）。

持久化

每节点 SaveCheckpoint（全量 State 快照）+ 会话 UpdateSessionCAS 乐观锁（冲突不视为失败）+ 消息落库携带 token usage。

LLM 韧性

429 / 5xx 重试 1 次（退避 1s）；60s 超时；上下文取消不重试。客户端仅依赖标准库，实现 agent.LLMClient，可换任意 OpenAI 兼容 provider。

审核期开关

feature.agent_enabled 总开关 + review_versions 黑名单：审核中的小程序版本强制关闭 AI 顾问，过审后远程放开。

§ 06

一条请求的旅程

把上面所有部分串起来——一条「浦东 705 平行志愿能去哪」从进入到返回，经历了什么。

  1. 入口 · ChatRequest
    小程序带 device_id / session_id / message / context 发到 Connect-RPC AgentService.Chat；API 层做协议转换。
  2. AgentService 前置关卡
    输入内容安全 → 每日配额 → 会话获取/创建 → 会话级锁 → 重建 State（历史消息 + session 槽位 + 前端 context 并入）→ 全局并发闸 → 落库用户消息。
  3. Router
    识别为 recommendation，抽出槽位 district_name=浦东新区, total_score=705，置信度足，进入 Planner。
  4. Planner
    必填槽位齐全，规划两步：locate_score（定位达线学校）+ get_score_trend（看目标校稳定性）。
  5. Executor
    errgroup 并发跑两工具，各产出 ForLLM JSON + Cards；5s 超时与 panic 保护兜底。
  6. Synthesizer
    把工具结果作为唯一数据来源，综合出带年份、分制、冲稳保建议的草稿回答。
  7. Reflection
    verifyReply 逐数字核对——705、各校分数线、gap 全部能溯源 → 通过。放行到 End。
  8. 出口 · ChatResponse
    输出内容安全 → CAS 更新 session → 落库助手消息（带 token usage）→ 返回 reply + school_cards + tool_calls + trace_id。

这是 折桂登高 AI 顾问 Agent 的架构总览。核心实现位于 backend/internal/service/agent/（graph/ 状态图、tools/ 工具集）、agent_service.go（编排）、infrastructure/llm/（LLM 客户端）。

数据仅供参考，以上海市教育考试院官方公布为准。
